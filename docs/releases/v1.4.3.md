# pi-workbench v1.4.3 发布说明

> 桌面工具：把指令集模板与 65 个技能模块部署到 PiDeck（~/.pi/agent）或 DeepSeek Harness（$DSH_HOME），卸载即还原。
> 本版只改首页两处交互，修的是「注入完了为什么没生效」这个反复踩的坑。无破坏性变更。

## 一、下载与校验

| 文件 | 说明 |
|---|---|
| pi-workbench-v1.4.3-windows-x64.zip | Windows x64 onedir 目录包，解压即用（无需 Python / Node） |
| SHA256SUMS.txt | 上面这个 zip 的 SHA-256 |

校验：Get-FileHash .\\pi-workbench-v1.4.3-windows-x64.zip -Algorithm SHA256，与 SHA256SUMS.txt 比对。
解压后双击 pi用学习工作台\\pi用学习工作台.exe；结果文件写在 exe 同级 data\\ 下。

## 二、首页：注入后没重启客户端会直接提示

DSH 只在**客户端启动后**的会话首次请求里读 ~/.dsh/AGENTS.md，而且**不监听外部改动** ——
客户端开着的时候注入，当前会话和新开的会话都不会生效，必须重启客户端。

现在卡片会自己比对：状态清单的 installedAt vs 客户端最老进程的启动时间（GetProcessTimes，零第三方依赖）。
客户端早于注入时显示：

> ⚠ 客户端需重启才生效 —— 注入于 10-21 22:00:22，而客户端进程启动于 10-21 21:52:41 ……

判据取不到（客户端没在跑 / 拿不到时间）就不显示，不猜也不误报。

## 三、卸载：按钮挪走 + 确认框写清后果

原来的按钮是「注入 / 重启 / 卸载 / 体检 / 版本」并排，卸载紧挨着重新注入，误点一次就把指令段和
65 个技能一起删了 —— 这正是之前「过一段时间新对话失效」的真实原因之一。

- 「卸载」改名「卸载注入」，单独一行、靠右、小一号（28px），不再和注入挨着；
- 确认框直接列出会拿走的三样东西 + 技能数与示例名，并明写
  「卸载后所有新会话都不再有指令集与技能，要重新注入才会回来」，
  末尾补一句「只是想让改动生效的话，注入后重启客户端即可，不用卸载」。

## 四、启动即以管理员运行（UAC）

exe 的 manifest 声明 `requireAdministrator`（`bj_tool.spec` 里 `uac_admin=True`），双击即弹 UAC。
原因：之前实锤过「写 `~/.dsh` 的临时文件被拒 + 回滚失败 → AGENTS.md 半坏」，那是权限层的问题，
在工具逻辑里永远修不干净；一次性提权比事后补救可靠。

- 运行日志首行与设置页都会写当前权限（管理员 / 普通用户）；
- 非管理员启动时设置页那行变黄，提示右键「以管理员身份运行」；失败提示里的提权重试仍保留作兜底；
- 代价：每次启动弹一次 UAC；批量脚本/计划任务拉起会被拦（需要时可改成任务本身「以最高权限运行」）。
