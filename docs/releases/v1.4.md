# pi-workbench v1.4 发布说明

> 单文件桌面工具：把指令集模板与 65 个技能模块部署到 PiDeck（`~/.pi/agent`）或
> DeepSeek Harness（`$DSH_HOME`），卸载即还原。
> 本版是**工程加固版**：一个升级兼容缺口、五处会导致「静默不生效 / 静默装错」的
> 真实缺陷，加上合规声明、进程树回收、自我部署脚本与验收进仓库。无破坏性变更。

## 二、修掉的静默缺陷（本版重点）

这几条的共同特征是：**不报错、不提示，但结果不是你以为的那个。**

### 修：`Copy-Tree` 静默不覆盖（影响面最大）

`robocopy` 的默认规则是「**大小相同 + 时间戳相同 = 已相同**」，**不看内容**。
技能包里的 `SKILL.md` 常是同一秒解压/生成的，于是「换个来源重装同名技能」
会静默保留旧内容。

实测（同一对文件，源 94B / 目标 94B，mtime 完全相同但内容不同）：

```
/E /IS        -> rc=0，目标纹丝不动   （include 开关救不了）
/E /IS /IT    -> rc=0，目标纹丝不动
/MIR          -> rc=0，目标纹丝不动
先删目标再拷   -> rc=1，内容正确更新   （唯一可靠）
```

根因：robocopy 在**目录层**就把「判定为相同」的条目整体跳过，而 include 开关
只作用于文件层。现改为「**先删目标再整份复制**」，与本工具「整份接管」的语义一致。

`Copy-Tree` 有 **6 处调用**，包括同名技能覆盖与**备份还原** —— 也就是说
「还原」此前可能并没有真的还原。

### 修：DSH patch 层标记块每次部署累积一层

`Strip-PatchBlock` 的定位正则末尾有 `$`，而它被包在 `(?s)` 里：
.NET 多行模式下 `$` 匹配的是 `\n` 之前的位置，`[^\r\n]*` 之后还隔着 `\r`，
**条件无解、模式永不匹配** → 旧块从来没被摘掉 → 每次部署追加一层。

实测修复前：连部署 3 次得到 3 个 `BEGIN/END`。
README 承诺的「重复注入幂等：标记块替换而非叠加」在这一层是失效的。

现改为：`[^\r\n]*` 本身已是精确行尾锚定，去掉冗余的 `$`；`(?s)` 收窄为块内
`(?s:...)`。顺带利用 `Replace` 替换全部匹配 —— **老用户已有的累积块一次清理干净**。

### 修：移除附加包后状态不一致 + 菜单未重建

`-RemoveAddons` 原先只更新 `installedSkills`，`menuKeepAdvertised` 仍指着
已删的包。该字段是「极简模式下保持进提示词」的例外名单，下次部署会对不存在的
路径调 `Remove-DisableModelInvocation` 并**静默失败** —— 「保持常驻」这个承诺
永远无法兑现，而 `-Check` 从不读这个字段，发现不了。

现在：移除时同步剔除该字段 + 按移除后的技能集重建菜单技能正文。

### 修：`-Probe` 归属误判 + 隐藏泄漏被掩盖

- 原先用 `-match` 做**子串包含**，而技能名存在 **5 对包含关系**
  （`reverse-engineering` ⊂ `reverse-engineering-api`、`l-reverse` ⊂ `seagull-reverse` 等），
  会把「泄漏了 `reverse-engineering-api`」记成「泄漏了 `reverse-engineering`」。
  改为按行取词 + 精确比对。
- 原先 `hit` 判定先于 `hid`，导致「答出了菜单技能 **+ 同时泄漏了隐藏模块**」
  被判成 `pass` —— **隐藏标记失效被掩盖**。改为隐藏泄漏优先。

### 修：只读保护勾选报错

`TemplatePage._on_readonly_toggle` 调用了 `self._set_status`，但该函数定义在
`MainWindow` 上 → 勾选只读保护会抛 `AttributeError`，界面看着「没反应」。

## 三、v1.4 新增的能力

### 加：重名技能来源选择（`-SkillSourceMap`）

`-SkillsSource` 支持多来源（分号分隔），两个包里有同名技能时总有一个被跳过。
此前只能靠调整分号顺序表达偏好，**界面上没有任何入口**。

```powershell
# 默认：重名取先出现的那个（保持历史行为，不阻塞）
# 指定：让 dup-skill 取自 packB
powershell -File inject.ps1 -Target dsh -SkillsOnly `
    -SkillsSource '.\packA;.\packB' -SkillSourceMap 'dup-skill=packB'
```

冲突文案会同时报出「取了谁 / 跳过谁 / 怎么改」。指定了**不存在的来源**则
停下且不写入任何技能 —— 绝不静默退回默认，那等于用户的选择被无视。

### 加：进度「清单先行 + 逐项点亮」

PowerShell 一启动就干活，而进度窗是点了按钮才构造的 —— 只靠逐项事件会让
窗口挂载前的那几步永远停在「待办」。现在：调用方先算好完整清单、窗口构造时
就把行画全，后端事件只负责按 key 点亮；结束时仍未点亮的行标「**跳过**」
（后端有些步骤在特定条件下不发事件，兜这一层否则用户以为卡死）。

### 加：子进程输出分级

噪声前缀黑名单 + 关键行白名单（**白名单优先**，避免误丢含 `ERROR` 的噪声行）
+ 关键行截断 160 字符 + **过滤计数上报**（丢了多少行必须可见，不能静默吃掉日志）。

### 修：标记块升级兼容（真缺口）

以前定位标记块用的是**写死的整串** `<!-- BEGIN pi-workbench v4 -->`。
一旦以后改版本号（v4 → v5），旧块会被当成「没有标记块」→ 重复部署会**追加第二块**。

现在改成「**关键串 + 载荷**」：定位只认 `<!-- BEGIN pi-workbench`，版本号只是载荷。
- 旧版本块（`v3`）、旧版脚本写过的变体（`BEGIN pi-workbench prompt=x.md`）都能被认出来
- 重新部署**原地升级**（只换标记行，正文不变），BEGIN/END 计数恒为 1
- `-Check` 报出当前标记块版本；旧版本给 WARN 提示
- `skill_tool.py contract` 新增断言：定位正则必须基于关键串 —— 改回写死会直接报错

### 加：备份保留策略

`%LOCALAPPDATA%\pi-workbench\backup\` 以前**只增不减**。现在：
- 时间戳备份与 `backup\drift\` 各保留最近 **10** 份，多余自动清理
- **被状态清单引用的「唯一原件」永不清理**（那是卸载还原的命脉，删了就无法回到安装前）

### 加：渲染后占位符断言

指令集模板 / 菜单技能 / DSH patch 层在写入前会检查是否残留 `{{...}}`，
有残留直接报错停下（而不是把一堆占位符写进你的配置）。

### 加：合规声明（发布合规缺口）

- `NOTICE.md` 拆成三段：**许可范围**（哪些是原创）/ **第三方组件**（各自许可优先）/
  **再分发限制**（不得随包再分发的组件）
- 新增 **`THIRD-PARTY-NOTICES.md`**，由 `py -X utf8 skill_tool.py notice --write` 自动生成：
  带独立 `LICENSE` 的技能包（含子目录）、标注作者的技能、声明许可的技能，
  以及 **未声明来源的技能 59 个**（如实列出，再分发前须自行确认权利人）
- `skill_tool.py pack --exclude-bare`：需要「再分发安全包」时排除这些未声明来源的技能
- `contract` 校验 NOTICE 三段式 + 第三方清单与磁盘一致（数量不符即报错）
- 本版同时**修正了第三方清单里三个 LICENSE 的 sha256**（此前是陈旧值，与磁盘不符）

### 加：进程树回收（Job Object）

GUI 起 PowerShell 子进程时会把它挂进 `KILL_ON_JOB_CLOSE` 作业对象：
句柄关闭时由**内核**清掉整棵进程树（含孙进程），不依赖 `taskkill /T`，GUI 崩了也不留孤儿。
宿主自身已在别的作业（不允许嵌套）导致分配失败时，优雅回退到原来的 `taskkill` 路径。

### 加：`deploy-self.ps1`（自我部署）

```powershell
powershell -ExecutionPolicy Bypass -File deploy-self.ps1 -WhatIfOnly   # 只打印计划
powershell -ExecutionPolicy Bypass -File deploy-self.ps1 -NoStart      # 真部署但不启动
```

停进程 → 备份 `<exe>.rollback-<时间戳>` → 覆盖 → 校验 SHA256 → 重启；
结束时**直接打印回滚命令**；回滚备份按 `-KeepRollbacks` 清理；路径按脚本位置推导（不写死盘符）。

### 加：验收脚本进仓库

`tests/`（以前在 `%TEMP%` 被系统清理过一次，现在跟代码走）：

```powershell
py -X utf8 tests\run_all.py     # 12 个套件一次跑完
```

## 四、升级与兼容

- 从 v1.1 / v1.2 / v1.3 直接覆盖 exe 即可；状态清单与 `versionKey` 自动兼容
- 旧标记块（含更早版本写的）会在下次部署时**自动原地升级**，不需要手工处理
- **DSH 用户**：patch 层若已累积多个标记块，本版首次部署会**一次性清理干净**，无需手工处理
- 配置文件位置不变（`%LOCALAPPDATA%\pi-workbench\`）；本版首次部署会顺手清理多余旧备份
- `inject.ps1` 写入状态清单的 `toolVersion` 此前一直是 `1.0.0`（未跟着升版），
  本版修正为 `1.4.0`

## 五、已知限制（不夸大）

- 只作用于**文件**：写对文件不等于客户端已加载、更不等于模型已生效（用 `-Probe` 实测）
- 通道体检会发起**一次真实模型调用**（用你自己客户端的通道与额度），默认要你确认
- 未验证项：真实付费请求、服务端行为、第三方技能包内容的准确性 —— 见 `docs/SECURITY.md` 第五节
- 技能库中 59 个模块未声明来源/许可：再分发前请自行确认权利人（见 `THIRD-PARTY-NOTICES.md`）
- 仅 Windows
