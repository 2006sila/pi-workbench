# pi-workbench v1.4.1 发布说明

> 桌面工具：把指令集模板与 65 个技能模块部署到 PiDeck（`~/.pi/agent`）或
> DeepSeek Harness（`$DSH_HOME`），卸载即还原。
> 本版修技能库页两个「点了没反应 / 弹系统错误框」的按钮，并把发布形态从单文件改成
> onedir 目录。无破坏性变更。

## 一、下载与校验

| 文件 | 说明 |
|---|---|
| `pi-workbench-v1.4.1-windows-x64.zip` | Windows x64 onedir 目录包，解压即用（无需 Python / Node） |
| `SHA256SUMS.txt` | 上面这个 zip 的 SHA-256 |

```powershell
# 校验（把输出的哈希与 SHA256SUMS.txt 里的对比）
Get-FileHash .\pi-workbench-v1.4.1-windows-x64.zip -Algorithm SHA256

# 解压后：确认构建身份（结果写在 exe 同级 data\version-check.json）
$env:PJ_VERSION_CHECK='1'; .\pi用学习工作台\pi用学习工作台.exe

# 随包资源自检（结果写 data\bundle-check.json：ok / 技能数）
$env:PJ_BUNDLE_CHECK='1'; .\pi用学习工作台\pi用学习工作台.exe

# 界面关键路径自检（应用内编辑器读 → 改 → 原子保存 + 目录兜底；无界面，退出码 0 = 通过）
$env:PJ_UI_SELFTEST='1'; .\pi用学习工作台\pi用学习工作台.exe
```

## 二、根因：直接启动 explorer.exe 必崩

技能库页「目录」按钮点了会弹 `explorer.exe - 应用程序错误`，错误码
`0xC0000142`（`STATUS_DLL_INIT_FAILED`）。实测结论：

| 启动方式 | 结果 |
|---|---|
| 直接 `CreateProcess` 启 `explorer.exe`（任意参数 / creationflags / cwd） | **0xC0000142 崩溃** + 系统错误框 |
| 清空 PyInstaller / Qt 环境变量后再直接启 | 仍然 **0xC0000142** |
| 交给系统外壳（`ShellExecute` / `os.startfile` / 已运行的资源管理器） | 正常 |

也就是说问题不在权限、也不在环境变量，而在「谁去创建这个进程」。而旧实现除了走错路径，
还把「卡在崩溃提示框上的进程」当成启动成功（`wait(timeout)` 超时即视为成功），
所以既不打开、也不给提示 —— 从用户视角就是「点了没反应」。

## 三、修法

**目录按钮**：只请系统外壳与已运行的资源管理器代劳，不再新建 explorer.exe 进程。

```
os.startfile（ShellExecute 委派）
  └─ 失败 → ctypes SHOpenFolderAndSelectItems（进程内调用，交给已运行的资源管理器）
       └─ 失败 → 应用内目录浏览器（列文件 / 双击查看编辑 / 复制路径 / 再试系统）
```

**编辑按钮**：改为**应用内编辑器** —— `QPlainTextEdit` + 原子写保存（同目录临时文件 +
`os.replace`）+ Ctrl+S + 未保存关闭提醒。零外部进程，因此与「能不能启动系统程序」彻底解耦，
任何权限下都能用；需要外部工具时，对话框里保留「用系统程序打开」（走文件关联）。

**发布形态**：单文件 → onedir。启动不再自解压到 `%TEMP%`（旧单文件版在 `%TEMP%` 被安全软件
拦截的机器上会直接弹 "Could not create temporary directory"）；整体拷贝目录即安装，删除目录即卸载；
数据根默认就近放在 exe 同级 `data\`（便携，可用 `PJ_WORK_ROOT` 覆盖）。

## 四、验证（均在打包后的 exe 上实测）

- `PJ_BUNDLE_CHECK=1` → 退出码 0，`bundle-check.json`：`ok=true`、技能 65
- `PJ_UI_SELFTEST=1` → 退出码 0（应用内编辑器读取 / 修改 / 原子落盘 + 目录兜底列表）
- 技能页三个行内按钮（目录 / 编辑 / 删除）回调参数正确：`_checked=False` 默认参数，避免
  Qt `clicked(bool)` 覆盖默认实参

## 五、已知边界

- 「目录」按钮在系统外壳被策略或安全软件拦截时不会报错框，而是直接给应用内目录列表 ——
  这是有意的降级，不是失败。
- 删除 / 启停仍受目标目录 ACL 约束：被系统拦截时会提示「以管理员身份重启工作台」。
- 应用内编辑器按 UTF-8 保存（读入时容忍 BOM），换行统一为 LF。
