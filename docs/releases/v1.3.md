# pi-workbench v1.3 发布说明

> 单文件桌面工具：把指令集模板与 65 个技能模块部署到 PiDeck（`~/.pi/agent`）或
> DeepSeek Harness（`$DSH_HOME`），卸载即还原。本次为功能版，无破坏性变更。

## 一、下载与校验

| 文件 | 说明 |
|---|---|
| `pi-workbench-v1.3.exe` | Windows x64 单文件，双击即用（无需 Python / Node） |
| `SHA256SUMS.txt` | 上面这个 exe 的 SHA-256 |

```powershell
# 校验（把输出的哈希与 SHA256SUMS.txt 里的对比）
Get-FileHash .\pi-workbench-v1.3.exe -Algorithm SHA256

# 确认你拿到的是哪个构建（结果写 %LOCALAPPDATA%\pi-workbench\version-check.json）
$env:PJ_VERSION_CHECK='1'; .\pi-workbench-v1.3.exe
```

## 二、这个版本新增了什么

### 写坏了能退回去（事务与版本）

- **原子写**：先写同目录临时文件再替换 —— 进程写到一半被杀不会留半截文件
- **逆序回滚**：部署中途失败自动撤销本次已写入的内容（脚本级 trap 兜底），`state.conflicts` 记下回滚不成功的项
- **基线漂移拦截**：部署之后文件被外部改过 → 卸载/恢复默认停下（**退出码 3，不写任何文件**），
  `-Force` 才继续，且先把改动另存到 `backup\drift\`
- **版本日志 + 按版本恢复**：每次部署留一条 `backup\<目标>\history\<id>.json`（写前写后全文 + 双哈希）；
  `-ListVersions` / `-Restore <id>`；恢复前验 `afterHash`
- **恢复前可先看差异**：`-Diff <id>` 行级 diff（`-` 当前有 / `+` 恢复后会有），版本窗口里点「看差异」即可，只读

### 装完能确认「到底生效没有」

- **通道体检 `-Probe`**：加载层不联网查每个技能能不能被客户端发现（缺 `description` 会被静默跳过）；
  通道层真跑一次客户端 CLI 问模型「你现在能看见哪些技能」→ `pass / fail / mismatch / unclear / timeout / unrun`
- **通道预检**：配置根里没有 provider 配置、或没有可核对技能时直接报「预检没过（未发起模型调用）」，不白花调用
- **`-Check` 加两段**：加载层抽检 + 生成物一致性（菜单技能是否与当前技能库/类目表一致）
- 结论落 `state.evidence.channelProbe` 与 `last-run-*.json`

### 部署前先把活说清楚

- **任务构建器**：5 档位（MAX/FOCUS/BUILDER/RESEARCH/CREATIVE）× 7 通道 × 3 输出格式（markdown/json/code）
  → 生成五段式任务契约（工作约定 / 任务输入 JSON / 交付要求 / 输出格式 / 完成检查），一键复制；
  3 个预设（代码交付 / 方案研究 / 结构输出）；`-Compose` 同一份实现，**只生成文本，不联网不写配置**
- **操作留痕** `logs\operations.log`：一行一次操作（时间/目标/动作/状态/exit/skills/mode/drift/conflicts）

### 维护与自检

- **类目声明链路**：技能自己在 `metadata.x-pj-class` 里报类目，`skill_tool.py gen` 机械生成索引（不再手维护、不会漏登记）
- **部署契约** `deploy-contract.json` + `skill_tool.py contract`：随包资源 ↔ 磁盘 ↔ `bj_tool.spec` ↔
  标记块 ↔ 退出码 ↔ 模板锚定串 ↔ README 溯源，互相核对
- **技能库打包** `skill_tool.py pack`：zip + 内嵌 `MANIFEST.sha256`，同输入同字节，`--verify` 查篡改/丢失
- **发布前安全检查** `docs/SECURITY.md`：读写面、网络面（**工具自身零网络**）、已实现对策与未验证项

## 三、升级与兼容

- 从 v1.1 / v1.2 直接覆盖 exe 即可；旧 `versionKey` 会自动迁移
- 状态清单新增 `versionId` / `evidence` 字段，**旧清单无需手动改**：首次部署会补齐；
  体检在旧清单上也能写入结论（缺 `evidence` 会自动新建）
- 配置文件位置不变（`%LOCALAPPDATA%\pi-workbench\`），卸载前的内容照旧可还原

## 四、已知限制（不夸大）

- 只作用于**文件**：写对文件不等于客户端已加载、更不等于模型已生效（这是 `-Probe` 存在的理由）
- 通道体检会发起**一次真实模型调用**（用你自己客户端的通道与额度），默认要你确认
- 未验证项：真实付费请求、服务端行为、第三方技能包内容的准确性 —— 详见 `docs/SECURITY.md` 第五节
- 仅 Windows（`taskkill` / `robocopy` / PowerShell 5.1 依赖）
