# Task Boundary · 任务边界守卫

## 定位

**干活前/干活中**的边界控制，与交付后的 `code-quality-gate` 评分互补：
那个管"干得好不好"，这个管"有没有多干、有没有跑偏、有没有越权"。

核心哲学：**把当前责任承担完整，让复杂度随真实需要增长。**
必要的工作（调用方、数据迁移、测试）要做全，哪怕 diff 更大；
没有当前用途的扩展就停下。

## SHIT 四类反模式（命中即停）

| 缩写 | 反模式 | 判定 |
|------|--------|------|
| **S**cope creep | 范围膨胀 | 修一个问题顺手重构无关模块。必要的调用方/迁移/测试要一起处理；无当前用途的扩展停下 |
| **H**ashing & hardening | 无用防御 | 没人读取的 checksum、为想象中的未来搭的兼容层。防御要能发现问题并触发拒绝/恢复/诊断；有效保留，无用省掉，有害修好 |
| **I**ntent violation | 意图越界 | 说了只读 Review，文件还是被改。审查就报告问题，修改需要授权 |
| **T**ask thrashing | 任务打转 | 无新问题时把读过/测过/审过的再来一遍。有效证据就复用；代码或验收条件变了再补 |

行数、文件数、检查次数不能代替判断。

## 任务模式（先声明，后干活）

开始任务前先确定模式，用户没说就推断并明示：

| 模式 | 权限 |
|------|------|
| `review` | **只读**。报告问题，不改文件 |
| `answer` | **只读**。回答问题，不改文件 |
| `monitor` | **只读**。持续检查和报告 |
| `change` | 允许完成**请求内**的修改及其必要连带（调用方/测试/迁移） |

规则：
- `change` 不覆盖显式边界；要越过边界（加依赖、动锁定文件、算 hash），先说明理由再动
- 必要工作不等于授权扩张：修配置迁移 → 迁移+读写双方+兼容测试是必要；顺手升级依赖版本不是
- 只读模式中发现必须改才能继续 → 报告阻塞点，等授权，不擅自动手

## Stop Ladder（五级判断，加机制前过一遍）

1. **理解当前责任**：要交付的结果、显式边界、必须保持的既有保证。
   追完受影响的调用方和失败路径再选修法。计划或"更容易的子集"不算交付。
2. **从直接方案开始**：项目已有代码 → 标准库/平台原生 → 已安装依赖。
   行为、失败处理、状态生命周期对得上就用，不穷举生态。
3. **有具体缺口才扩展**：说清直接方案没覆盖的输入/消费者/失败/义务。
   已有的支持承诺算当前需要；"未来可能的灵活性"不算。diff 变大若是为了补全受影响流程，正当。
4. **按效果判防御**：说清机制能发现什么、它的拒绝/恢复/诊断改变什么。
   有效的保留；无具体用途的可选新增暂缓；吞错报成功、重复副作用、挡住正常工作的防御要修。
5. **验证完成即结束**：用项目既定检查覆盖受影响行为。证据对最终状态仍有效就复用。
   请求的结果存在、必要证据支持、无范围内阻塞 → 结束，不再加"最后确认一下"。

## 不确定性处理（不许发明工作）

- 真实的信任边界、失败模式、已有数据、适用义务可以**先于事故**建立防御的必要性
- 说不清用途的新机制可以暂缓；用途不明的既有保护先查清调用链再动
- **缺证据 ≠ 不必要**。为了读一个新 manifest 而加的 verifier 不构成价值；要沿链回溯到任务需求或既有保证
- 普通选择从上下文解决；只在"信息无法从上下文获得、且会实质改变结果/授权/不可逆决定"时才问
- 被阻塞的必要检查：能就地修复就修，修不了就准确报告阻塞，**不宣称完成**；无关命令的成功不能替代缺失的证据

## 交付纪律

- 报告结果与相关验证；tradeoff/警告/限制只在**影响读者决策**时写
- 内部过程叙述、防御性免责段落不进交付物；不确定的主张收窄范围而不是裹免责声明
- 结束标志：请求的结果存在 + 必要证据支持 + 无范围内阻塞。满足即停，不追加"以防万一"

## 与 code-quality-gate 的配合

- 交付前发现自己在写"以防万一"的代码 → 回到 Stop Ladder 第 4 级
- 干完活后说"按质量门禁自检" → 走 `code-quality-gate` 评分流程
- 本 skill 不打分；它阻止多余工作进入 diff，从而让门禁评分更高

## 红线

- `review`/`answer`/`monitor` 模式下一律不写文件，哪怕"顺手改一行更快"
- 未声明的 hash/checksum 计算默认多余，除非发布流程消费它
- 不为"想象中的批评者"写代码或注释
- 结束就是结束；不发起没有新问题的重复验证
